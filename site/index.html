SELF-DRIVING SAFETY / NHTSA CRASH REPORTS

Turn crash narrativesinto auditable fields.

Self-driving companies file each crash with NHTSA as a written story plus checkbox fields. The auditor reads the story, fills each field with a quoted line of evidence or says "not stated", and queues every mismatch for a human.

Try the demoSee the evaluation

THE PROBLEM

Free text hides the root cause.

Autonomous-vehicle teams triage incident reports for anomaly detection, perception failures and long-tail scenarios. A useful assistant must distinguish what the narrative says from what it only guesses.

This project reads the narrative, extracts the crash partner, roadway type, other party movement and injury severity, then says not stated when the evidence is silent.

THE OUTPUT

A claim with its proof attached.

Pydantic rejects extra keys, enumerations keep answers comparable, and a substring check prevents invented quotes. The result supports telemetry pipelines, evaluation and first-pass yield without pretending the filed label is perfect.

HELD-OUT EVALUATION

Selective extraction beats a flattering guess.

On the 1,196 field values the narratives actually state, the extractor matches the filed value 81.2% versus 40.6% for majority guessing on the same values, abstains on the rest, and every evidence quote is checked (99.9% exact).

QUEUED FOR HUMAN REVIEW

Disagreements are signals, not verdicts.

The queue counts filed/model value pairs and keeps one recorded example for each common pair. Roadway type and injury severity barely beat or tie majority because one filed category dominates each field, and narratives rarely state property damage.

METHOD

Code checks the model.

The model handles language. Python handles the boundary: schema validation, exact evidence spans, date splitting and the accuracy math.

  1. Get the data

    Load the public NHTSA Standing General Order ADS CSV and keep the narrative plus its filed fields.

  2. Extract

    Ask Claude Haiku 5.5 for four enumerated fields and one evidence span per field.

  3. Verify

    Reject unknown labels, extra keys and evidence that is not an exact substring.

  4. Compare

    Score each field against the report's structured columns and a keyword baseline.

  5. Review

    Queue up to 50 disagreements for a human check instead of treating the filed field as ground truth.
